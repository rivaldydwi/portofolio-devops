// EVOLUTION

How this pipeline grew

  1. PHASE 01 AWS

    Started with AWS EC2

    Built the first working CI/CD pipeline. GitHub Actions triggered on every push, built a Docker image, and deployed it to an EC2 instance. It worked — but the monthly bill didn't.
    GitHub Actions Docker AWS EC2
  2. PHASE 02 SELF-HOSTED

    Moved to a Mini PC

    Cut cloud costs entirely by deploying to a self-hosted server at home. Used Tailscale VPN to connect the GitHub Actions runner securely — no public port exposure needed.
    Tailscale VPN Self-hosted SSH Deploy
  3. PHASE 03 IaC

    Added IaC + Monitoring

    Replaced manual docker run commands with Terraform. Infrastructure is now version-controlled, consistent on every deploy, and smart enough to skip restarts when nothing has changed. Added Trivy scanning at two checkpoints, and set up real-time server monitoring with Prometheus + Grafana + Node Exporter.
    Terraform Trivy IaC Prometheus Grafana Docker Hub Slack Notify
  4. PHASE 04 NOW

    Container Orchestration with Kubernetes

    Deployed the monitoring stack (Prometheus + Grafana + Node Exporter) onto k3s — a production-grade Kubernetes distribution running on the same Mini PC. Infrastructure is fully declarative via YAML manifests, self-healing, and ready to scale. This sits alongside Docker Compose — demonstrating both approaches for the same workload.
    k3s Kubernetes kubectl Deployment ConfigMap NodePort
